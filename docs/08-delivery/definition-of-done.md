# Definição de pronto

- História e etapa identificadas; contrato e fluxo alinhados ao PRD e ADR.
- Validação de entrada, autorização, idempotência e conflito cobertos quando aplicável.
- Testes unitários, integração ou jornada correspondentes ao risco passam localmente e em CI.
- Migração/índice com verificação e rollback operacional se houver mudança de dados.
- Logs de sucesso/falha claros sem segredos ou texto pessoal; falha externa permite caminho de recuperação.
- Toda documentação afetada atualizada na mesma entrega: README completo, PRD, ADRs, contratos, dados, segurança, operação, testes, backlog e artefatos Spec Kit; registrar áreas não afetadas com justificativa.
- README descreve o estado real, configuração sem segredos e comandos existentes/verificados; links válidos e propostas identificadas como futuras.
- Demonstração Telegram/Web da etapa; arquivo e resultados de testes apresentados na revisão.
- Funcionalidade de etapa futura não é criada como requisito oculto do MVP 1.
